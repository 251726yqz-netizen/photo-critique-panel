# 0.3.0：从并列观察到有立场的批评

日期：2026-10-15（Asia/Tokyo）。本次改变评片行为，未增加人物生平事实、来源条数或声称进行了新一轮作品全集研究。

## 已观察到的问题

0.2.0在实际使用中逐位覆盖和出处边界基本成立，但同一种“观察—保留—比较两个版本”的短段落反复出现。批评常把选择延后交给练习，未充分论证当前照片的得失；各席虽然关注点不同，读起来仍像一个温和的讲评者。用户明确要求更鲜明的立场、更直接的批判与更详细的理由。

这一失败是表达和判断契约的问题，不是缺少22个口头禅。0.3.0保留资料、来源及F/I/R映射，给每个档案追加标明为技能作者推导的评审立场；它们不构成人物真实性格档案或对其全部生涯的概括。

## 改变了什么

- 22张独立立场卡：优先标准、质疑重点、愿意辩护的选择、改变结论的条件、论述节奏及关键追问。每卡回指本人的现有I/R。
- 逐人依据及修改前后档案哈希见 [变更映射](critical-change-map.json)，原有F/I/R正文和来源记录逐字保留。
- 每席应论证当前照片：可见细节如何改变注意、空间、时间或叙述，为什么该变化符合或违背其标准。动作建议必须说明收益与代价。
- 对成立的选择积极辩护；不按固定负评配额捏造缺陷。缺少相关材料时明确保留，不用假设作品集、复拍或调查代替这张的评价。
- 取消每席相同的五字段展示，保留证据与出处契约。来源靠近相应判断，通用资料局限在末尾说明一次。
- 综合保留实质冲突，说明采用哪种目标才应选择哪项行动。可以保留不改图的结论。

## 验证原则

见 [批评行为场景](../tests/critical-scenarios.json) 和 [评估记录](../tests/results/critical-assessment.md)。结构校验不测审美。每次模型回应必须人工看是否给出可核对的理由，而不能用字数、尖锐词数量或不同昵称代替判断。

私人照片可在获得用户指令后本地使用；本仓库只发布既有公共测试材料上的示例及抽象方法，不上传私人图像、本地路径或原始私人评片。单次试验不证明跨模型稳定，也不把人工写作示例计为独立模型测试。
